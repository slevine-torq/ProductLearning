# Module 4 · Pre-Read: Build High-Velocity Product Roadmaps

> ~10 minutes. Read this before class so we can spend our time building, not catching up.

## Why this module matters

In Modules 1 to 3 you framed a problem, discovered it qualitatively, and turned it into a data-backed hypothesis. Module 4 is where strategy meets execution. You'll learn to **prioritize ruthlessly**, **scope a lean MVP**, and **prove your solution works** with a clickable prototype, before a single engineer is committed.

The through-line: **a roadmap prioritizes high-leverage problems, not a wish-list of features, and the fastest way to de-risk a feature is to build a prototype of its logic, not argue about it.**

## The three things to anchor on

1. **Prioritize on Effort vs. Value.** A roadmap is a *visual strategy*, a *prioritized sequence*, a *living document*, and an *outcome map*, not a backlog of everything anyone asked for. Score each initiative on **Value** (the lift on your M3 metric) and **Effort** (the engineering cost). The four quadrants tell you what to do: **Quick Wins → Now**, **Major Projects → Next**, **Fill-Ins → Later**, **Time Sinkers → cut.** Aim for a 70 / 20 / 10 balance of core / adjacent / exploratory.
2. **Scope with the MVP and MoSCoW.** An MVP is the most pared-down version that still delivers the core value, the shortest line between a user's *moment of misery* and their *moment of value*. Slice scope with **MoSCoW**: a **Must-Have** is a ship-blocker; a **Should-Have** is high-priority-if-capacity; a **Could-Have** is next-sprint polish; a **Won't-Have (now)** is an explicit exclusion that prevents scope creep. The test: *"if we remove this, can the user still achieve the primary outcome?"*
3. **PRD → prototype, in a rapid loop.** The **Simplified PRD** is a functional blueprint, not a bureaucratic document, it centralizes the *why*, forces clarity, and bridges strategy to execution. Feed it into an AI prototyping tool, test the output, find the logic gaps, update the PRD, and re-run. You iterate in minutes, not sprints, then bring stakeholders a *working model* for the alignment handshake.

## Key terms (full list in the Glossary)

- **Effort vs. Value matrix**: a 2×2 that sorts initiatives into Quick Wins, Major Projects, Fill-Ins, and Time Sinkers.
- **Now / Next / Later**: the three roadmap lanes; what ships this sprint, next, and what waits in the backlog.
- **70 / 20 / 10**: a healthy split of roadmap capacity across core product, adjacent growth, and exploratory R&D.
- **MVP**: the most pared-down solution that still delivers the core value proposition.
- **MoSCoW**: Must / Should / Could / Won't-Have; a framework for slicing scope.
- **Simplified PRD**: a lean, functional Product Requirements Document that doubles as the prompt for an AI prototyping tool.
- **Rapid validation loop**: prompt → test → find gaps → update PRD → repeat, until the logic is bulletproof.
