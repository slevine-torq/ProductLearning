## Task 1 — Choosing Metrics That Matter

### Block: Metric Key Terms — Type: Card flipping

1. Term: Vanity metric | Definition: A number that measures an action rather than an outcome — it can climb while the user is no better off.
2. Term: Counter-metric | Definition: The metric you watch to make sure a win in one place isn't quietly causing a loss somewhere else.
3. Term: Leading indicator | Definition: A signal you can influence today that predicts a later result — the thing worth actually chasing.
4. Term: Lagging result | Definition: An outcome you can only observe after it's already happened. By the time it moves, it's too late to act on it directly.

### Block: Real or Vanity — Type: Card classification

**Buckets:** Proves value, Measures activity only

1. "Total dollars moved through the new feature" → Measures activity only
2. "Percent of users still active 30 days after first use" → Proves value
3. "Total clicks on the new button" → Measures activity only
4. "Percent of users who completed the core task, unassisted" → Proves value

## Task 2 — The AARRR Funnel & the Outcome Hierarchy

### Block: Funnel Key Terms — Type: Card flipping

1. Term: AARRR | Definition: Acquisition, Activation, Retention, Revenue, Referral — the five-stage map of the user lifecycle, often called "Pirate Metrics."
2. Term: Activation | Definition: The stage where a user first experiences real value — one of the two stages a product build can move most directly.
3. Term: Retention | Definition: Whether the value became a habit — the other stage a product build can move most directly.
4. Term: Multi-sided funnel | Definition: On any product with more than one user type, each type runs its own version of the funnel — and they're often coupled to each other.

### Block: Stage Check — Type: Quiz

1. Which two AARRR stages does a product build typically control most directly?
   A. Acquisition and Referral
   B. Activation and Retention ← correct
   C. Revenue and Referral
   D. All five equally

2. On a two-sided marketplace, advertiser spend depends most directly on:
   A. How the advertisers feel about the brand
   B. Whether the supply side (e.g. creators) keeps showing up ← correct
   C. Nothing — it's an independent metric
   D. The acquisition budget alone

## Task 3 — Slicing and Sizing the Problem

### Block: Slice or Size — Type: Card classification

**Buckets:** Segmentation (finds where), Cohort analysis (sizes how urgent)

1. "Breaking a metric down by device type" → Segmentation (finds where)
2. "Tracking January's users separately from June's users over time" → Cohort analysis (sizes how urgent)
3. "Comparing new users to power users" → Segmentation (finds where)
4. "Checking whether newer groups retain worse than older ones" → Cohort analysis (sizes how urgent)

### Block: Analytics Key Terms — Type: Card flipping

1. Term: Cohort | Definition: A group of users who all started at the same time, tracked separately to see how their trajectory compares to everyone else's.
2. Term: Decline (a leak) | Definition: Newer cohorts dropping off faster than older ones — the product is getting worse for new users and needs a fix.
3. Term: Flatline (a ceiling) | Definition: Every cohort stalling at the same point — the product is stable but stuck, and needs a real improvement, not a fix.
4. Term: Result signal | Definition: A top-line number like total revenue or average value — tells you the scoreboard, not what to do next.

## Task 5 — From Data to a Defensible Hypothesis

### Block: Hypothesis Audit — Type: Card classification

**Buckets:** Passes the audit, Fails the audit

1. "Users want a better experience." → Fails the audit
2. "Simplifying the signup form will reduce 7-day drop-off from 40% to 25% for new mobile users." → Passes the audit
3. "Adding an AI summary will improve engagement." → Fails the audit
4. "Based on interview evidence that setup is confusing, non-technical users will complete onboarding 25% more often if we cut the required fields in half." → Passes the audit

### Block: Bet Type — Type: Card matching

1. Prompt: Optimizing the existing | Match: Fixing a known workflow — you're chasing retention or conversion.
2. Prompt: Exploring something new | Match: Validating an unproven need — you're chasing activation and early signs of value.
3. Prompt: Guardrail metric | Match: The number that must not drop while you chase the win.
4. Prompt: Decision window | Match: How much time or data you need before you scale, pivot, or kill the bet.
