Turning AI output into strategy

Ask an AI for a roadmap and it'll hand you a clean-looking list in seconds. Whether any of it deserves engineering time is a separate question, and it's the one you're actually paid to answer.

Course Strategic Product Thinking Hands-on ~15 min Artifact Three-Prompt Escalation + reflections

Run the same request through an AI three times, escalating the context you give it. The output evolves from a generic feature list into something you could actually defend in a roadmap conversation. The point isn't the mindmap — it's seeing exactly where your judgment is doing the work.

Before you start

Confirm your engagement's AI policy and approved tools before putting any client specifics into an AI tool. If client detail is off-limits here, run this on a consumer product you know well instead — the lesson is about prompt structure and your judgment, not the subject matter.

The three-prompt escalation

Run each prompt in a fresh chat so the AI doesn't build on earlier context. Swap the bracketed placeholders for your own product.

Step 1 · The shallow ask

Generate the baseline

Give it almost nothing. This is what an order-taker's prompt looks like.

Create a mindmap for [your product].
Now find the weak spot.

Find one item on that map you couldn't defend if an engineer asked "why this, this quarter?" No answer tied to a real customer or a real number means you'd be shipping the AI's guess as if it were your own call.

Step 2 · Add structure

Give it a role and real context

Now the output will look organised. Watch what that does and doesn't fix.

You are a product manager. Create a mindmap for [your product],
which helps [who] accomplish [what].
Include features, user needs, and potential problems.
Find the plausible-but-empty one.

Name a feature that looks entirely correct for this product but carries zero strategic weight — you have no idea whether it helps the business or whether a single real user has ever asked for it. Organisation is not strategy. The AI can group things; that doesn't mean it knows what's a good use of engineering's time.

Step 3 · Strategic framing

Layer in the judgment

This is where you supply what the model can't: the frames a product decision actually gets made against.

You are a senior product manager preparing for a discovery sprint on
[your product], used by [specific user] who [specific behaviour or friction].

Create a structured brainstorm mindmap organised around:
1. Core user jobs-to-be-done
2. Key friction points in current behaviour
3. Feature ideas ranked by effort vs. impact
4. Monetisation or business-value paths, with the trade-off each carries
5. Retention risks, and how each could be addressed

Flag any area where there is a real strategic tension worth debating.
Find the tension.

Point at one place where the output surfaces a genuine trade-off — two things that can't both be optimised. That tension is the actual raw material of a strategy conversation.

Compare V1 to V3

Line up the first output against the third and be honest about the source of the improvement: did the model do that, or did the context you fed it do the actual work?

Nothing changed about the model between step one and step three. What changed is that you supplied jobs-to-be-done, effort versus impact, monetisation trade-offs, and retention risk. You converted a feature-generating tool into a strategic one by knowing which frames to hand it.

The pattern

The more specific your product context, the better the output. AI organisation is not the same as strategy. Just because a model can create tidy groups doesn't mean it knows what's a good use of engineering's time. The AI executed — you thought.

Short, but worth writing down — these are the observations that make the next AI-assisted task faster.

Key takeaways

  1. Organisation isn't strategy. A model that can group ideas neatly still has no idea what's worth the team's time.
  2. The frames you supply are the value you add. Jobs-to-be-done, effort vs. impact, monetisation trade-offs, retention risk — that's product knowledge, and it's what turns generic output into something defensible.
  3. Plausible output is the dangerous kind. An obviously wrong suggestion gets caught. A reasonable-looking feature nobody asked for gets shipped.
  4. The AI executes; you think. Speed on the grind is real — the judgment call stays yours.
