Frontend frameworks

What "we're a React shop" tells you in three words, the cross-platform question that actually settles the argument, and one name collision worth checking every time.

Course How Software Is Built Read time ~9 min

Frontend is what the user sees. When a client says "we're a React shop," they've just told you their hiring market and their component reuse story in three words — and left out the part that actually costs money.

React, and the thing people leave out

React is component-based and declarative: you describe what the interface should look like for a given state, and when the state changes React re-renders what changed. It's the default choice in frontend and the lowest hiring risk by a wide margin.

The part that gets left out: React is a library, not a full framework. It handles rendering. Routing, state management, data fetching, and forms are all assembled by the team from other pieces. Which is why two React codebases can look nothing alike, and why "we know React" doesn't mean an engineer knows this React codebase.

So the real risk was never React. It's the bespoke assembly around it, which is where onboarding cost and lock-in accumulate — and which nobody lists when they name their stack. Ask what's around it.

React Native, and two companies who both got it right

React Native renders genuine native UI components rather than a web view. Business logic is shared across iOS and Android; platform-specific behavior still needs platform-specific code. The honest trade is one team and roughly 70–90% shared code, against edge-case pain in animation, gestures, deep OS integration, and debugging across the JavaScript/native boundary.

Both public outcomes are real, and that's the useful part:

AirbnbAbandoned it, 2018A five-part public explanation of why it didn't work for them

Neither was wrong. They had different requirements. Which is exactly why walking into a client conversation with a view on React Native is a mistake — you don't yet know which of those two situations you're in.

The questionDoes this product's differentiation live in native platform capability?

If yes, cross-platform costs you the thing you're selling. If no, you're funding two mobile teams for no strategic return. That's a headcount decision worth several million dollars over the life of an engagement, and it turns on one question rather than on anyone's framework preference.

Angular, Vue — and the name worth checking

Angular is a full opinionated framework: routing, forms, HTTP, and dependency injection all included, written in TypeScript. That prescriptiveness is a real advantage on large teams that want one right way to do things; the costs are a steeper learning curve and a smaller hiring pool than React. Vue sits between the two — more structure than React, less than Angular.

A client on Angular is not a problem. A client on AngularJS is a different conversation entirely. AngularJS is the discontinued 1.x line, end-of-life since December 2021, which means running unsupported software.

The names are dangerously similar and people use them interchangeably without meaning to mislead you. Confirm which one they mean, every time. This is a security and compliance finding rather than a technology preference, and it is not the sort of thing you want to discover in month four.

Bootstrap, and how styling is organised

Bootstrap is a CSS framework with a responsive grid and pre-styled components, dropped in via a stylesheet. It's enormously fast for internal tools and admin panels where nobody needs a distinctive look. For a customer-facing brand experience it's the wrong tool — you'll spend more overriding it than you saved.

Which makes it a useful signal. Bootstrap in a customer-facing product usually means the product was built without design involvement, and that's often the actual root cause sitting behind a client's "our UX is bad" complaint.

Beyond Bootstrap, modern styling means Flexbox and Grid for layout plus a token-based system, commonly through Tailwind or CSS-in-JS. Task 1 covered why the presence of that system decides what a UI change costs; here just find out concretely which one the team uses, because "we have a design system" and "we have a Figma file nobody implemented" sound identical until you check.

Progressive Web Apps

A PWA is a website that can be installed, work offline, and send notifications, without going through an app store. It's a genuine third option in the native-versus-cross-platform debate: no App Store review, instant updates, one codebase. The cost is reduced access to device capabilities and weaker discovery.

Worth raising in any mobile scoping conversation where the client's main driver is release speed rather than device capability — it skips App Store review and its revenue share entirely. It's frequently not considered at all, which makes it a cheap thing for you to add to the discussion.

Regulated client?

If you're engaged with a healthcare, aerospace & defense, or financial-services client, an end-of-life framework like AngularJS is likely to fail a compliance scan or a vendor security review outright, and remediating it needs legal/compliance review, a longer approval cycle, and scheduling early rather than at the end. Assume "we'll upgrade it later" is a compliance question before it's a technical one.

Tier 1 — a level deeper

React is the default, React Native is React for mobile, Bootstrap is pre-built styling, a PWA is an installable website. That's enough to follow the conversation. The one active thing to do is check Angular versus AngularJS, because it's a real finding and nobody will be annoyed you asked.

The move: ask which Angular, and write down who told you.

Tier 2 — the trade-off you can discuss

You can hold the cross-platform conversation now, and the way to hold it is by asking the differentiation question rather than offering a view. Shopify and Airbnb reached opposite conclusions and both published why; that's your evidence that the answer is situational.

The move: "does your differentiation depend on native capability?" — then let them answer it.

Tier 3 — strategic & risk read

Cross-platform is a headcount decision worth millions across an engagement. End-of-life frameworks are compliance exposure with a remediation cost that belongs in the estimate. And the bespoke assembly around React is where the real onboarding and lock-in cost sits — which matters directly to what a clean handoff will take.

The move: price the assembly around the framework, not the framework.

Key takeaways

  1. React is a library, not a framework. The bespoke assembly around it is where onboarding cost and lock-in actually live.
  2. Airbnb dropped React Native and Shopify committed to it, both publicly. Different requirements, not different levels of judgment.
  3. One question settles cross-platform: does the product's differentiation depend on native platform capability?
  4. Angular and AngularJS are not the same thing. The 1.x line has been end-of-life since December 2021 — confirm which one, every time.
  5. Bootstrap in a customer-facing product is a signal. It usually means design wasn't involved, which is often the real story behind "our UX is bad."
